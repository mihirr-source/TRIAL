API Reference

All endpoints are JSON over HTTP. Interactive OpenAPI docs: /docs (Swagger UI) · /redoc

GET /api/health

Service status, catalogue version, sync mode, retrieval mode and index stats.

{ "status": "ok", "catalog_version": "2026.09-seed-2",
  "retrieval_mode": "lexical",   // or "hybrid" with embeddings installed
  "sync": { "mode": "seed", "last_synced": "2026-09-29",
            "snapshot_records": 0 },   // "seed+snapshot" after an import
  "stats": { "catalogue_size": 84, "alias_count": 612 } }

GET /api/search?q=…&top_k=6

Hybrid semantic + alias search. Multilingual queries supported (English, Hindi, Tamil, Telugu vocabularies). Returns primary plus ranked alternatives with confidence scores and matched aliases.

curl "http://localhost:8002/api/search?q=cooling+unit+for+office"

POST /api/analyze

Full tender analysis. Body: {"text": "…"} (10–20,000 chars). Returns primaries with confidence, missing allied/normative standards, mandatory certification alerts, obsolete/unknown code flags, and a RAG health-check summary.

curl -X POST http://localhost:8002/api/analyze \
  -H "Content-Type: application/json" \
  -d '{"text": "Supply of packaged drinking water in 20 L jars. TMT bars per IS 1786:2008."}'

POST /api/analyze/file

Tender-document intake: multipart upload of a PDF or DOCX (≤ 10 MB, ≤ 50 PDF pages). Text is extracted and the same analysis pipeline runs. Scanned/image-only PDFs are rejected with a clear message (no OCR).

curl -X POST http://localhost:8002/api/analyze/file -F "file=@tender.pdf"

POST /api/spec-clauses

Draft tender clauses per identified primary: correct code + latest known edition + amendments, allied standards to cite, and the mandatory certification sentence. Copy-paste into a specification — then verify.

curl -X POST http://localhost:8002/api/spec-clauses \
  -H "Content-Type: application/json" \
  -d '{"text": "Split air conditioners for the training hall."}'

POST /api/analyze/export?format=markdown|json

Download the analysis report as a Markdown tender-review document (attachment) or JSON.

POST /api/assistant

Plain-language assistant. Body: {"message": "What is IS 456?", "lang": "en|hi|te"}. Template mode (default) answers only from the catalogue; with BIS_LLM_API_KEY set, an LLM rephrases the same grounded sources in the requested language and the response reports mode: "llm". Every reply cites only catalogue-backed codes.

curl -X POST http://localhost:8002/api/assistant \
  -H "Content-Type: application/json" \
  -d '{"message": "Does a pressure cooker need ISI mark?", "lang": "en"}'

GET /api/standards[?sector=electronics]

Browse the catalogue; filter by sector key (construction, cement, electronics, appliances, water, food, safety, steel, pumps, furniture, medical).

GET /api/standards/{code}

One standard's detail: version, amendments, aliases, allied standards, certifications, spec pitfalls. Loose matching: IS 13252 resolves to IS 13252 (Part 1).

GET /api/certifications

All mandatory certification schemes mapped in the catalogue with the standards they apply to.

Offline catalogue import

The supported data path is an offline CSV snapshot — no live crawling:

python -m bis_engine.data.importers.bis_snapshot --input snapshot.csv
# template: bis_engine/data/snapshots/template.csv
Data status: the engine runs on a curated seed catalogue for demo purposes. Before production use in any procurement workflow, replace it with a licensed/live BIS data feed and legal review of every recommendation.
